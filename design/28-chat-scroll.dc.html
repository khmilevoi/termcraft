28 · Chat scroll & history paging ws-scroll-loaded-120 · ws-scroll-mid-120 · ws-scroll-loading-120 · ws-scroll-failed-120 · ws-scroll-start-120 · ws-scroll-live-120 · ws-scroll-narrow-80

Lives here rather than folded into §02/§03: those own the panel's idle and generating shells, and §24 owns chat-list navigation, but neither owns the message stream's own scroll mechanics — that's new surface, so it gets its own number.

The stream is now a real viewport over everything the client holds, and reaching its top pages the rest of the chat in from disk. ▲ N earlier messages keeps its exact wording, but its meaning and its nature both change: N now counts records not yet loaded, not rows scrolled out of view — that count is unknowable and stays undrawn, forever — and the row stops being a summary. It becomes the first row of the loaded content: you scroll to it, and reaching it is what triggers the next page load. Mouse-down works there too. Once every record is on the client (N = 0) but the buffer is still taller than the viewport, the row simply isn't drawn — see ws-scroll-mid-120, ordinary chat lines sit flush against the top edge with nothing above them, because how many loaded rows are above the fold is exactly the number this design never computes.

A 1-column scrollbar rides the sequence's right edge — solid amberDim track glyph, amberDim thumb built from █ and half-cell ▀/▄, no end arrows. It's the one position cue this design draws, because it's a ratio the widget computes itself, not a count. No number anywhere reports how far up you are, how many rows sit below the fold, or how many messages arrived while you were reading — none of those are ever computed, so none are ever almost-right.

A "newer below" signal exists, but it's not a floating badge. It reuses the pinned row above the composer that §08 already draws pin-attach text into — ▼ scrolled up · ^D follow latest — because that row already means "something about the stream you should know before you type," and this is one more thing it can say. No new chrome, and it never claims a count.

Keys: PgUp / PgDn scroll the viewport (mouse wheel too — line-wise); ctrl+d jumps to the newest message and resumes following. Plain letters and ctrl-arrows are both off the table here — the composer is live and swallows printable characters, and ctrl-arrows are dead on the maintainer's terminal (§03's composer stays focused throughout; nothing above steals it). F5/F6 are already spoken for by the crash-recovery surface, so a failed page load doesn't get its own key — it reuses PgUp, the same gesture that asked for the page, printed right on the error row. Both hotkeys are drawn in the status bar's key row wherever they apply, never assumed.

The start of the chat is a dead end, not a target. ╌╌╌ start of chat ╌╌╌ is centered, faint, and carries no arrow — nothing loads from reaching it, so it draws nothing that invites reaching it again.

Scrolling away and a running turn are independent. ws-scroll-live-120 combines them: the live block still tails and folds exactly as §03 defines — untouched — off the bottom of a viewport that's scrolled elsewhere. The banner is the same ^D follow latest row, just amberHi instead of amberHi-on-request: it can say a turn is running below, never how much it's grown.

80 columns keeps the vocabulary. §08's narrow chat panel drops its scrollback row outright because it's competing with pin text for the same width; this row has no such competitor and the label fits in 27 usable columns, so ws-scroll-narrow-80 keeps the ▲ row and the scrollbar both — dropping them here would hide that history is unreachable, which matters more now that paging exists.
