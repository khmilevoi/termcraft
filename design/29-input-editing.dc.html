All four text inputs — the Workspace composer, the Home prompt, the pin field, and the slash-menu filter (the composer's own buffer) — move onto a real edit buffer: a cursor anywhere in the text, word jumps, word-wise delete both directions, undo/redo, select-all, and for the composer and Home prompt, word wrap with a growth ceiling and internal scroll. None of that had anywhere to render before this: every caret in this system was drawn one column past the end of the text, and the composer was a fixed four-row block. This page collects all four inputs' new states in one place rather than editing §01/§03/§08/§23 in place, because the load-bearing change — a character actually sitting under the cursor — is one primitive shared by all four, and every frame below leans on it; splitting that across four files would either repeat the explanation four times or hide the seam. §01/§03/§08/§23 are unchanged and still correct: every single-row frame they show renders exactly as before, because that is the frozen path (below), and this page is the second path.

One terminal, one cursor. Exactly one of the four inputs paints a cursor at a time; the spec's focus table decides which. The two rows that differ visually and are drawn here: a turn running with an empty draft stays focused with no cursor painted (§03's wsGenLong already draws this), a turn running with a non-empty draft is focused with the cursor painted (§03's wsGenTyping already draws this, extended past one row below). Everything else — overlays, preview focus, read-only, Home's blocked health state — blurs the input and paints nothing, unchanged.

No affordance for a chord that isn't universal. Shift+Enter, Ctrl+Backspace and Ctrl+Shift+Z need the enhanced keyboard protocol and are silently absent in a legacy terminal with no way to detect which is running — so none of them is drawn as a hint anywhere on this page. Newline is also Ctrl+J / Alt+Enter, word-delete-back is also Ctrl+W, redo is also Ctrl+Y — universal fallbacks, but still not drawn as key-row hints below, on the same logic §03 already applies to a bare esc: it says what a gesture does, never teaches a chord in the chrome. The one new hint that does appear is ^A select all (§29.5) — a plain Ctrl+letter chord in the same family as ^W/^Y/^J, none of which need the enhanced protocol. Otherwise the status bar says nothing new: mode chips and the F2/F3/F4 keys are the same ones §02/§03 already draw.

The cursor, and the frozen single row

Every existing frame in §01–§28 is the single-row case, and it is frozen exactly as drawn: one input row, the caret past the end of the text. What's new is a second path, reached only when the cursor sits before the end of the text or the buffer holds more than one visual row. ws-editor-midword-120 is the smallest possible instance of the new path at the old geometry: still one row, still frameH-4, but the cursor has moved left into "network throughput panel" and the g of "throughput" now sits under it in reverse video — amber fill, background-coloured glyph, still blinking. That reverse cell is a drawn approximation of the terminal's own hardware block cursor: the app can only set style, blink and colour, and the terminal paints the real thing, so the divergence is carried as a code comment, not hidden.

Growth: wrap vs. an explicit newline

The composer is 1 seam row + an optional attach row + editorRows — frozen at editorRows === 1, exactly today's numbers. ws-editor-wrap-120 grows it to three by word wrap alone typing one long sentence with no newline anywhere; the seam rule and its codex · gpt5.5 · high / ctx chips move up with it, unchanged in every other respect. ❯ marks row 1 only — repeating it on every wrapped row would read as several prompts instead of one growing message — so continuation rows start flush under the same text column with nothing in the marker column.

ws-editor-newline-120 is the F6 repair fill (§12's wsHostCrash) rendered honestly for the first time: draft + "\n\n" + error produces a real blank row between the kept draft and the pasted error. That blank row is the whole answer to whether a wrap reads differently from a newline — it does, but not by decoration: wrap alone can never produce an empty visual row (a wrapped line always holds at least the one word that didn't fit above it), so a blank row is unambiguous proof of a real \n, no marker required. The buffer is split on literal newlines first and each resulting paragraph is word-wrapped after, so this is exact, not inferred.

The ceiling, and scrolling inside it

editorRows = clamp(visualLines, 1, clamp(floor(frameH/4), 1, 6)) — 6 rows at 120×36, 5 at 80×24, a proportion rather than a constant so the smallest supported terminal isn't squeezed to nothing. Past the ceiling the view scrolls and follows the cursor, and unlike §28's message stream — where a count of hidden rows above genuinely doesn't exist — the whole draft is already in memory here, so an exact integer is available at both edges at once. ws-editor-ceiling-120 shows the cursor mid-buffer with rows hidden on both sides: ▴2 / ▾4, one corner glyph on the first and last visible row, exact counts, never a row of their own. That is deliberately not §28's ▲ N earlier messages — that row names a destination worth paging to; this glyph names a window that only ever follows the cursor automatically, and costs zero rows because a grown composer's row budget is the expensive thing here (see the 80×24 floor, below). The two vocabularies share a project but not a meaning, and now they don't share a shape either.

The slash filter, now editable in the middle

The slash filter is the composer's own buffer, so it inherits everything above: ws-slash-editor-120 opens the menu above a composer already grown to two rows, cursor mid-word inside reasoning on the wrapped line — ←/→ and ^←/→ now reach into the middle of a filter for the first time. ws-slash-closed-64 is the new edge case the spec calls out: delete the leading / and the menu closes, but the remaining characters are not discarded — they stay in the composer as ordinary literal text, because closing the menu is a matcher decision, not an edit.

Home grown, and the pin field overflowing

home-grown-120 — the describe box grows downward from a fixed top, so the logo and tagline above it never move; ⏎ create, the agent/model/effort selectors and the slash menu all shift down with it, because the menu's anchor (iy + boxH) was already dynamic and simply follows. pin-overflow-64 is the opposite case: the pin field never wraps or grows — one line, always — so it is the only input where text scrolls out of view sideways. The window follows the cursor exactly like the composer's vertical scroll, and a single ‹ marks the hidden head; typing at the end never clips the tail, so › only appears once the cursor moves back into the middle of overflowed text.

The 80×24 floor

At the narrowest supported terminal a maxed 5-row composer takes 7 of the panel's 22 content rows; the live agent block sits on its own 3-row minimum; scrollback is squeezed to zero — no room for even one summary row above the live block. Nothing marks that the conversation continues the way §28's ▲ N earlier row would, because there is no row left to spend on it. What still tells the reader is what already existed for exactly this shortage: the header line (● codex) never disappears, and §28's proportional scrollbar — a column, not a row — still tracks against the full history at zero row cost. ws-floor-80 draws this floor plainly rather than inventing a new affordance to say what an existing, cheaper one already says.
