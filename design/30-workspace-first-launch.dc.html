Reopening an existing project used to hold the user on Home — the describe the TUI… screen — for the whole ~30s the project takes to open. That screen was never true for this wait: nothing here is a fresh design. The Workspace now mounts immediately, with projectId still null, and fills in one jump when the open finishes. This section is new rather than folded into §02 or §12 because it is a full sequence — a start state, an outcome, and a long-lived side effect on the bar — and collecting it in one place keeps that sequence legible; §02's idle shell and §12's error frames are otherwise untouched.

Mid-open no page, no chat, no cancel, nothing measurable

Distinct from two frames that assert different facts: §20's No pages yet is a finished project that genuinely has none, and §14's ⠹ generating first page… is a running, cancellable turn. Here neither is true, so the preview centres a plain amber line with no glyph in front of it — nothing spins. A spinner is turn vocabulary; drawing one over a state with no cancel and nothing measurable would borrow a promise this state can't keep. The tab strip is empty (no ghost — that exists only mid-turn) and the chat panel has no header line: agent identity is unknown until the open finishes, exactly as it is everywhere else per the spec.

The status bar's page slot is filled, not dropped — opening project…, Home's own phrase, reused verbatim in the slot that's free because there's no page slug yet. The mode chip reads OPENING, not STATIC: STATIC asserts a finished, unchanging design, which is exactly the claim this state can't make. The composer stays live — placeholder project opening… — but ⏎ is refused, and the key row is where that shows: a faint, disabled ⏎ send. F2/F3/F4 are dropped rather than drawn inert — none of the three have anything to act on yet (no preview, no page to tweak or interact with), and Home's own checking state shows the same restraint, offering only its one live key plus quit.

The long-lived badge a fully open, working project — the probe never re-runs

The probe runs once at startup and is never refreshed, so a bad reading rides in the hint slot for the life of the process — over a project that is otherwise working normally. Below, a main page, a finished design, ordinary STATIC chrome — and a permanent ✗ codex not signed in badge sitting where a turn's own hint would go if one were running. Composer, preview, history, export and tweaks all still work; only sending a turn does not, and the badge is the only thing that says so.

The collision — halted preview, dead agent preview halt outranks health in the hint slot

Both can be true at once: the preview host has crashed and latched (§12's HALTED), and the agent probe separately reads blocked. The hint slot holds one badge, and the halt's own render crashed keeps it — it is the more urgent, more specific fact, and it's already the reason this frame exists. What changes is a real problem the halt block would otherwise paper over: its F6 route reads repair… and promises a turn, but with the agent dead that turn cannot run. The block's F6 line is rewritten to say so, and a line is added under the tee rule making the same point plainly, rather than the composer quietly swallowing an ⏎ that goes nowhere.

The badge vocabulary as read in a workspace bar, not Home's

Precedence, highest first: read-only → turn running → preview halt → agent health → none. Turn running must outrank health by rule — a live turn demonstrates the agent is alive, so a stale bad reading under it would contradict what's on screen. The rest of the order is this section's own call: health sits last among the real tiers, ahead only of showing nothing. It is a permanent, ambient fact, not an urgent one — it competes for the slot only when nothing more immediate already needs it, which is exactly when a quiet, always-on signal is most legible and least in the way.

Five outcomes, four shapes — ready draws nothing, matching Home. missing has no badge on Home at all (it takes over the whole screen there); this is its first, invented from the takeover's own words.

Chat panel, question 3 unchanged — the honest answer is silence

No line is added to the empty panel above. §28's ╌╌╌ start of chat ╌╌╌ marker means "you scrolled up and there's nothing more to load" for a project with real history — a claim about paging that doesn't apply to a project with no chat loaded yet at all.
