03 · Workspace — generating ws-gen-120

Agent status streams in the chat (spinner + step lines); the preview keeps the currently applied design dimmed with a subtle generating indicator.

A running turn is one ordered list, not two lanes: tool steps and reasoning rows appear in the order they happened, so the block reads thought → action → thought → action. Reasoning no longer replaces itself — that ticker rule is superseded, but the compactness it protected is not, so the block is bounded (below).

Steps hold the left edge; reasoning hangs off a thread. A step starts with its glyph in column one (✓ done, ▸ running, ✗ failed). A reasoning block puts a │ rule in column one and its text one column further in, wrapping under itself, so a block of prose fuses into one vertical strand and the step glyphs stay scannable straight down the margin — indentation and faint alone stopped separating the two the moment reasoning became multi-line.

Reasoning is prose, and only the current block gets room. Measured blocks run 248–491 characters — eight to thirteen wrapped lines in a 44-column chat pane, so three of them at full length would bury every step row. So the block the agent is on tails: it wraps and keeps its last 5 lines as it streams, exactly like text scrolling in a terminal, with ┊ on the first line where the head scrolled away. The moment the agent moves to the next step that block collapses to its first line plus … — a bookmark, not a transcript. Every past thought costs exactly one row, so the shape of the turn stays readable no matter how verbose the model is.

Three weights, one glance. Live block: amberDim rule, dim text. Collapsed block: line-coloured rule, faint text. Steps stay at full weight above both. What it is doing now, what it is thinking now, what it already thought.

The block is capped at 12 rows and folds from the top. The spinner row is pinned; everything above the tail collapses into one ┊ ▲ 6 earlier thoughts · 5 steps row — same ▲ N earlier language as chat scrollback (§08), dashed rule to say the strand continues rather than starts, and the same dashed glyph that marks a tailed live block, because both mean the same thing: lines elided above. Folding from the top, never the bottom — the newest rows are the ones being read. See ws-gen-long-120, where two earlier exchanges are still on screen under a turn twenty-five rows deep.

Elided reasoning is not recoverable in the live block — no expand key, no scroll inside the turn. The running block is a progress indicator; the finished turn still collapses to its persisted record exactly as before. Open: if operators ask to read a scrolled-past summary in full, that wants its own surface (a reasoning pager), not an affordance crammed into this block.

The composer is not disabled — typing and editing the next message is allowed, only sending is refused. Empty, it shows the faint ❯ generating… esc to cancel placeholder with no caret. Holding a draft it looks alive, because it is: amber ❯, text in full foreground, blinking caret. The refusal is stated twice and never by greying the input — the line above the caret reads ⏎ send disabled — draft kept, and the status bar renders its ⏎ send key faint instead of amber while esc cancel stays live. Same faint-key convention as the Home health check (§01). / on an empty composer still opens local command mode (§23).
